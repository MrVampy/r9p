# Plan 83 Response Freshness Slice

Date: 2026-07-02.

Question: how should session responses start carrying freshness evidence now that the session owner has feed state?

## Sources Checked

- Vault `docs/plan/83/index.md`: the minimal query contract requires per-response freshness with `session_epoch`, feed generation, and `fresh_instance`.
- `notes/source-reading/2026-07-02-plan83-query-contract.md`: freshness modes were deferred until feed/session state existed.
- `notes/source-reading/2026-07-02-plan83-session-feed-status.md`: feed state now tracks last event id, last generation, and fresh-instance cursor misses.
- `crates/session/src/control/mod.rs`: builds `session.status.v1`.
- `crates/session/src/control/tree.rs` and `query.rs`: route path-shaped and `/query` responses.
- `crates/session/src/control/snapshot.rs`: renders stat, list, read, and snapshot JSON.

## Findings

- `session_epoch` should be generated by the long-lived control owner at startup. It is not a CLI argument and not a backend fact.
- Snapshot/stat/list/read freshness can use one small control-owned descriptor derived from the session epoch plus current feed state. This keeps rendering honest without putting feed parsing into snapshot code.
- Feed generation is `null` until the feed has delivered an event. That is materially different from pretending the answer is synchronized.
- `sync`, `max_age`, and `must_revalidate` remain unimplemented. The response freshness descriptor is evidence for future enforcement, not the enforcement itself.

## Effect

- Add `crates/session/src/control/freshness.rs`.
- Generate a `session:<pid>:<nanos>` epoch when `serve_control_socket` starts.
- Add `session_epoch`, `feed_generation`, and `fresh_instance` to `freshness` in status, stat, list, read, and snapshot responses.
- Extend the integration proof so status contains a session epoch and query snapshots contain the synthetic feed generation.

## Open Questions

- Reconnect should bump or replace the epoch when the session owner gains transport-reconnect behavior.
- The `sync` freshness mode should wait for the feed worker to expose an explicit barrier operation against the current namespace head.
